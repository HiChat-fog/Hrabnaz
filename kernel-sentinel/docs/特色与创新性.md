# 内核哨兵特色与创新性

内核哨兵与现有终端安全工具（Falco、Tetragon、Tracee）相比，在六个维度上有明确的技术差异，每个差异点均有代码实现支撑而非概念设计。

第一个创新是内核态进程树实时追踪。Falco通过eBPF探针或内核模块在用户态维护进程缓存——新进程启动时加入缓存、退出时移除，目标是维护当前运行进程的快照。但缓存构建在用户态：短命进程可能因事件丢失导致缓存中无记录，PID复用场景下的父子关系可能错位，且Falco官方文档指出'所有spawned_process事件的历史记录不等于系统当前进程树'。Tetragon提供process_exec、process_exit和process_fork事件，fork事件携带parent_pid和child_pid字段，可通过关联构建进程树——但fork事件需显式启用（默认只捕获execve），且父子关系需在用户态手动关联，不维护一个始终有效的内核态拓扑图。内核哨兵在内核空间用BPF_MAP_TYPE_LRU_HASH维护pid到process_node的拓扑图，每次fork创建子进程节点并自动继承父进程风险分（child_node.risk_score = parent_info.risk_score），每次exec更新comm和exe_path，每次exit清理节点。进程节点维护四个标志位：PROC_FLAG_ROOT（uid=0进程）、PROC_FLAG_CONTAINER（容器内进程）、PROC_FLAG_ORPHAN（父进程已退出）、PROC_FLAG_ANOMALOUS（行为异常）。正常fork仅更新Map不发送ring buffer事件，异常情况（父进程风险分≥40导致子进程自动标记异常、黑名单进程关系如systemd→nc匹配）才向用户态发送告警。这使系统能检测"wget下载恶意文件后bash执行加密器"这类跨进程的攻击链，而Falco和Tetragon只能看到孤立的进程事件。

第二个创新是内核态TCP流状态机。Falco只检测单次connect调用不追踪流生命周期——攻击者建立C2连接后持续通信的行为无法从单次connect判断。Tetragon通过TracingPolicy在内核做事件过滤和策略执行，其TCP追踪聚焦于连接事件（connect/accept/send/recv）的捕获与过滤，但不维护每个连接的状态机去做C2心跳、数据外泄、端口扫描等异常模式自动判别。内核哨兵在内核空间用net_flows LRU Hash Map为每个TCP连接维护完整状态机，状态转换路径为SYN_SENT→ESTABLISHED→FIN_WAIT→CLOSED，通过kprobe/tcp_set_state跟踪内核TCP状态转换，通过kprobe/tcp_sendmsg累计传输字节。在此基础上检测五种异常：C2心跳（同一目标重复连接≥3次，bit0标记）、数据外泄（累计传输>100MB，bit1标记）、端口扫描（30秒内连接≥20个不同目标，bit2标记）、长连接异常（ESTABLISHED持续>24小时，bit3标记）、快速重连（30秒内断开重连，bit4标记）。正常连接仅更新Map不发事件，仅异常流和里程碑状态转换（ESTABLISHED/CLOSED）发送ring buffer事件，减少80%以上网络事件负载。这些判断在内核纳秒级完成而非等事件到达用户态再分析，对检测C2通信和DNS隧道等需要流级别视角的攻击有本质优势。

第三个创新是Field枚举的类型安全分发机制。Falco的规则字段基于字符串查找——如proc.name和proc.pname都是有效字段名。Falco对完全拼错的字段名（如field: xyz）默认会报错退出（skip-if-unknown-filter默认为false），这点值得认可。但更隐蔽的问题是：规则作者若误将proc.name写成proc.pname，两者均为合法字段名，Falco不会报错，但匹配目标已经错位——这种'字段名正确但含义错位'的静默逻辑错误是字符串查找机制无法防范的。Tetragon通过TracingPolicy的kprobe参数捕获，字段名与实际内核函数签名绑定。Tracee通过字符串事件名匹配，字段名正确性依赖文档。内核哨兵用Rust的Field枚举做类型安全分发：25个变体各自对应一个具体的Event结构体字段访问器，数值字段（pid、dport等）自动走数值解析后比较，字符串字段（comm、filename等）走字符串方法或正则，IPv6字段走专门解码逻辑。serde在YAML加载时校验field值是否在枚举范围内——完全拼错的字段名如field: xyz会直接报Err而非静默通过。但更关键的是枚举的分发机制消除了"字段名正确但含义错位"的可能——每个变体在编译期就绑定了唯一的字段访问路径，不存在运行时字符串查找的歧义。数值字段还额外支持regex/contains/startsWith操作符，将数值转为字符串匹配使端口号能用^(4444|1337|31337)$一条正则覆盖多个恶意端口。

第四个创新是z-score统计基线偏离检测替代硬编码阈值。Falco和Tetragon的异常检测用固定阈值——"每次可疑操作加固定分数，总分超过阈值就告警"。wget高频网络连接是正常的，bash高频网络连接是异常的，固定阈值无法区分。内核哨兵为每个进程建立六维行为基线（syscall、file_ops、net_ops、dns_ops、ptrace、signal各60秒窗口的平均值μ与标准差σ），偏离度用z = (current - μ) / σ量化。z > 2σ触发低风险偏离，z > 3σ触发中等偏离，z > 5σ触发严重偏离（severity 分级实际为 2/3/4/5 四档）。阈值自适应进程差异——wget的net_ops基线均值可能是200，bash的可能是5，wget当前300次偏离仅0.5σ不触发告警，bash当前20次偏离3σ触发告警。基线训练有一个关键设计：一次性训练锁定。当进程积累了5个以上已完成窗口（syscall_count > 1表示窗口有实质内容），pid加入established_pids集合，基线不再自动重算。原因是如果基线随异常数据持续更新，偏离度会被稀释——进程突然产生500次文件操作后，基线均值从5拉到40，z-score从55降到0.8，告警消失。需要手动调用refresh_baseline()才能重新训练，这模仿了机器学习中的训练-检测分离范式。在基线未建立前使用固定阈值fallback（syscall 5000次/60秒、file_ops 500次、net_ops 100次、dns_ops 50次、ptrace 3次、signal 10次），并内置18个"天生高频"进程标记（wget、curl、python、nginx、postgres等）避免冷启动误报（标记供判级参考，不自动放宽阈值）。

第五个创新是跨事件关联引擎弥补单事件规则的固有缺陷。Falco和Tetragon的规则引擎只能匹配单条事件——"读/etc/shadow后外连4444端口"需要两条事件，但daddr和filename不可能出现在同一个事件里，单事件规则的AND条件永远无法命中。内核哨兵的关联引擎实现三种关联类型：窗口关联在时间窗口内检查A事件和B事件是否同时出现，数据结构用VecDeque维护滑动窗口，置信度基础0.6加同PID加0.2；序列检测按步骤顺序追踪如勒索软件的读→加密写→删模式，步骤间间隔不超过max_gap，置信度基础0.7加3秒内完成额外0.2；进程树关联检查同一进程树中不同进程的行为组合。序列追踪器的键使用(rule_idx, pid)而非仅pid——如果多个序列规则共享同一个pid键，规则A推进tracker到step=2后，规则B（只有2步）看到step=2 >= steps.len()=2会重置tracker，破坏规则A的进度。独立键保证每个序列规则对同一进程有独立的追踪状态。当前定义8条关联规则覆盖数据窃取、SSH密钥窃取、勒索软件序列、反弹Shell、提权+持久化、DNS隧道、以及两条进程树关联（sshd→nc、cron→wget）。

第六个创新是内核态自动智能过滤层减少ring buffer负载。Falco将所有捕获事件发到用户态再由规则引擎过滤——正常ls打开普通文件这类低风险事件也走完整内核到用户态管道，浪费CPU和上下文切换开销。Tetragon通过TracingPolicy支持用户自定义内核过滤规则，但过滤策略需要人工编写和维护。内核哨兵的智能过滤采用自动判断无需用户配置：风险分过滤（risk_score >= 40 放行）、频率异常过滤（freq anomaly_flags 置位放行）、规则白名单过滤（已知安全模式如白名单进程+文件组合丢弃）。过滤决策函数should_send_event返回action（1=丢弃 / 0=放行）及具体原因，事件类型决定默认策略——文件open/read默认丢弃（低信息价值但高频），exec/connect/ptrace/signal等其他事件默认放行（高信息价值）。filter_stats_map用PERCPU_ARRAY避免锁争。这是8-30 重构后的语义（早期"目标过滤率80%"的旧策略已被替换，且注意 action 命名与语义相反）。这使系统在高负载场景下不会因ring buffer溢出而丢失关键告警。

上述六个创新点不是概念设计，每个都有对应的代码实现和单元测试验证。内核态三个模块（进程树追踪、TCP流状态机、智能过滤）的C代码已完整编写，5 tier 编译通过并在真机加载验证（6.17/5.15/6.1/3.10 端到端跑通，16 探针）。用户态三个模块（Field枚举、关联引擎、基线偏离）已在真机数据流上通过 168 个测试验证（含 14 个 e2e 攻击场景），0 编译警告。
