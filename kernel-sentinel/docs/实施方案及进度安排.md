# 内核哨兵项目实施方案及进度安排

## 实施方法与研究路线

项目采用"内核优先、逐层验证"的实施路线。整个系统的核心壁垒在内核侧——eBPF 探针和推理引擎的验证器通过是后续所有工作的前提，因此开发机到位后第一优先级是eBPF验证器调试和aya框架对接。研究范围界定为：内核态探针层、内核推理层、用户态引擎层、CLI交互层四个层级，不涉及Web前端和分布式部署（这些属于长期演进方向，不在本项目周期内）。技术路线按以下顺序推进：

第一步eBPF验证器调试。16 个探针（5 tracepoint + 11 kprobe）逐个通过验证器，每个探针可能需要5至10次修改才能通过（验证器限制：100万指令上限、8级调用深度（5.2+）、512字节栈、禁止浮点和无界循环）。infer推理引擎的手动字符串比较需要改为展开式固定比对而非循环，这是验证器最难接受的模式。✅ 已完成（5 tier 全编译通过）。

第二步aya框架对接。将eBPF程序的真实加载、ring buffer消费、BPF Map用户态读取从stub替换为aya-rs实现。aya API有生命周期和回调注册的坑，需要反复调试。完成后内核事件首次到达用户态。✅ 已完成（modern/legacy ringbuf+perfbuf 双路径，nobtf 内核走 C loader 旁路）。

第三步用户态模块接入真管道。当前correlation引擎、baseline偏离检测、process_tree模块在模拟环境下验证通过但未接入start.rs的事件消费循环。需要在循环中加入correlation.detect_correlations()、baseline.update_from_event()与detect_deviation()、process_tree.update_from_event()，并将它们的告警写入取证日志。BPF Map读取（进程树Map、频率计数Map）需要在aya对接完成后实现。✅ 已完成（start.rs 事件泵已接入四道检测）。

第四步探针架构冲突解决。vfs_probe和smart_filter都hook vfs_open函数，在真实内核上会冲突。解决方案是将smart_filter作为vfs_probe的前置过滤器通过BPF tail call串联，或在加载时只挂载合并后的单一探针。✅ 已解决——实际采用单编译单元方案：所有探针并入 `ks_main.bpf.c` 按序 include，vfs_open kprobe 直接调 `smart_filter_handle_vfs_open`，无 tail call。

第五步六攻击场景端到端验证。反弹Shell、勒索软件、提权攻击、DNS隧道、Rootkit、正常基线六个场景逐个在真实内核上运行，确认所有规则命中、关联告警触发、基线偏离检测生效、取证哈希链完整。每个场景需要模拟攻击脚本执行后检查告警输出和取证日志。✅ 已完成（12 攻击场景 e2e 14 测试 + 三机真机验证，另含容器逃逸/LKM/eBPF 篡改三安全探针）。

第六步性能基准测试。无探针基线→有探针→高负载（每秒10万事件）→不同规则集组合，测量探针延迟（目标小于1微秒）、事件吞吐（目标大于10万条每秒）、CPU占用（目标小于5%）、内存占用。多内核兼容至少验证5.15和6.1两个版本。✅ 已完成——口核对齐：内核侧捕获 13.6-52 万 syscall/s 达成 10 万目标；用户态端到端 1197-1977 events/s（瓶颈定位在取事件环节，见 performance-design.md §6）。

第七步CLI深度打磨。replay增加终端内ASCII时间线可视化，status增加实时事件流监控模式，新增baseline子命令查看和刷新基线，新增correlation子命令查看关联状态。新增watch子命令实时显示内核事件流和告警。✅ 已完成（8 子命令 + sparkline + --json + comfy-table）。

资源支撑：开发机为Linux 5.15+内核工作站，配备8GB以上内存和SSD存储，用于eBPF编译、加载和端到端验证。✅ 已到位并完成全部验证。开发机到位前在Windows上使用MockEventSource完成所有用户态模块的设计、实现和测试验证，168个测试已全通过。Docker Desktop用于编译验证（Dockerfile和docker-compose已配置），但Docker内无法做eBPF加载验证。

## 人员分工

项目的技术壁垒高度集中在内核侧和引擎核心，这部分只能由具备eBPF和Rust能力的人推进。其他成员各承担一个明确维度，保证项目在每个方向都有专人推进而非一人分身。

张航（项目负责人）承担系统架构决策和核心开发全栈工作。从内核探针层到用户态引擎层再到CLI骨架，所有需要深度技术判断的模块由张航设计并实现：eBPF C代码（16个探针+推理引擎）的编写和验证器调试、aya框架对接和ring buffer真实消费、内核推理引擎阈值调优、BPF Map用户态读取实现、探针架构冲突解决、correlation引擎、baseline偏离检测、process_tree模块的设计与开发、start.rs事件消费循环的模块接入、性能基准测试。开发机到位后张航全职在Linux环境工作，因为eBPF验证器调试需要持续迭代无法远程分工。张航也是唯一能处理跨层级问题的人——探针输出格式影响聚合器解码、推理引擎阈值影响用户态告警策略、ring buffer数据流影响整个管道——这些都需要同一个人同时理解内核侧和用户态侧才能做出正确决策。

刘晨承担测试设计与执行。张航写完模块后刘晨负责验证它能正确工作：编写correlation引擎窗口关联和序列检测的边界条件测试、baseline z-score偏离检测的多进程并发测试和基线锁定防护测试、SHA-256哈希链防篡改测试（手动修改JSONL后检查verify_chain是否报断裂）、六攻击场景端到端验证的测试脚本编写和执行、性能基准测试的对照组设计（无探针/有探针/高负载三组对照×两个内核版本）、跨内核兼容测试数据记录。刘晨不是跑一次就交差——每个新探针通过验证器后要重跑全量回归确保没有副作用，性能基准要设计对照组确保数据可比，哈希链防篡改要用实际修改文件的方式而非只测正常流程。开发机到位前刘晨维护和扩展现有84个测试到100以上，开发机到位后负责开发机上的测试执行和数据记录。

王磊承担CLI交互层开发。CLI是运维人员接触系统的唯一入口，做得好不好直接影响项目可用性印象。王磊负责：replay命令8阶段回放增强（哈希链校验→事件统计→类型分布→严重性分布→MITRE映射→攻击链可视化→进程行为画像→时间线ASCII图）、status从静态显示改为动态监控模式、新增baseline子命令（查看基线状态、手动刷新、偏离结果展示）、新增correlation子命令（关联规则状态、序列追踪进度）、新增watch子命令（实时事件流和告警）、输出格式统一（中文信息、表格对齐、颜色标注严重性）、serve改为CLI-first声明。王磊在开发机到位前完成所有命令的Mock版开发，到位后与真实数据对接。CLI的代码量不算大但用户体验细节多，需要独立一人专注打磨。

赵颖承担项目资料体系。评审看的是文档不是代码——赵颖的工作直接影响评审对项目完成度的判断。负责：ARCHITECTURE.md四层架构图更新（加入验证状态标注让评审知道哪些已验证哪些是设计）、ROADMAP.md按月度更新进度、前期设计文档持续修订（与代码演进同步）、API设计文档补全、教学指南六实验方案编写、安全设计文档威胁模型更新、性能设计文档目标值补充、ADR新增3条（进程树追踪、TCP流状态机、基线锁定）、YAML规则集使用手册、申报书各章节素材整理和排版。赵颖的工作贯穿全周期，核心要求是代码和文档必须同步——评审看文档时能找到代码实现，看代码时能找到设计说明，不能出现文档声称已实现但代码是stub的情况。

陈昊（项目组长）承担项目统筹与质量把关。作为组长，陈昊的工作不是写具体代码而是确保项目整体方向正确、各环节衔接顺畅。具体包括：需求对接——将比赛评审标准和申报要求翻译成技术任务清单，确保张航的开发工作始终对齐评审看重的维度（技术深度、设计依据、创新点可验证）；进度统筹——每周组织同步会跟进各成员交付状态，发现延误或方向偏离及时调整；质量把关——代码走查时重点检查接口契约完整性（模块间数据格式是否一致、pub函数签名是否稳定）、文档与代码是否同步（不能出现文档声称已实现但代码是stub的情况）、交付物完整性（每个阶段结束时确认测试报告、文档终版、演示材料齐全）；答辩准备——整理项目演示流程（开发机上从启动探针到触发告警到取证日志回放的全链路演示）、准备答辩PPT结构、梳理评审可能追问的技术问题（为什么选eBPF而非内核模块、z-score基线锁定的原因、进程树追踪与Falco的差异）。陈昊在开发机到位后统筹整体节奏——张航专注于验证器调试时陈昊确认其他成员的Mock版工作不偏离真实数据对接的需求，端到端验证阶段陈昊协调刘晨的测试脚本与张航的开发机排期。

分工的实际运作方式：张航输出核心模块代码后，刘晨验证功能正确性、王磊包装成CLI交互、赵颖同步写入文档、陈昊统筹进度和质量把关。这个流程保证每个模块经过五个人从不同角度处理，而不是一个人写完就丢进仓库。

## 进度安排

项目周期为2024年6月中旬至10月底，共四个半月，按月度划分五个阶段。

6月中旬至7月中旬（第一阶段：用户态完善与开发机准备）。核心任务：在开发机到位前完成所有可在Windows上推进的工作。张航完成用户态引擎层三个新模块（correlation、baseline、process_tree）与start.rs事件消费循环的Mock版接入，确保Mock环境下端到端流程完整。刘晨扩展测试覆盖：为correlation引擎新增窗口关联和序列检测的边界条件测试、为baseline新增z-score偏离检测的多进程并发测试和基线锁定防护测试、为process_tree新增进程退出后树清理的测试，目标测试总数从84提升至100以上。王磊完成CLI三个新增子命令（baseline、correlation、watch）的Mock版开发和现有命令的用户体验打磨，replay增加ASCII时间线可视化。赵颖更新ARCHITECTURE.md加入验证状态表格、更新ROADMAP.md记录当前进度、编写前期设计文档终版、整理YAML规则集使用手册。陈昊统筹第一阶段进度、确认各成员交付物与评审要求对齐、组织申报书素材整理。预期成果：100+测试全通过、CLI 8个子命令Mock版可用、文档与代码完全同步。负责人：张航（模块开发）、刘晨（测试）、王磊（CLI）、赵颖（文档）、陈昊（统筹）。

7月中旬至8月中旬（第二阶段：eBPF验证器调试与aya对接）。核心任务：开发机到位后第一时间推进内核侧工作。张航全职在开发机上工作：搭建开发环境（内核5.15+、clang-17、bpftool、Rust nightly工具链）、16个探针逐个通过eBPF验证器（每个探针预计需要3至5次修改，process_tree和net_flow因为用了LRU Hash和多步逻辑验证器难度最高）、infer推理引擎4个推理函数通过验证器、aya框架对接实现ring buffer真实消费、BPF Map用户态读取实现（进程树Map和频率计数Map）、探针架构冲突解决（vfs+smart_filter通过tail call合并）。刘晨编写开发机上的端到端测试脚本、每个探针通过验证器后执行回归测试。王磊将CLI命令从Mock数据源切换到真实数据源对接。赵颖记录开发机上的每次验证器修改和通过结果。陈昊统筹开发机工作排期、确认验证器通过顺序与回归测试衔接。预期成果：16个探针全部通过验证器、aya ring buffer对接完成、真实内核事件首次到达用户态。负责人：张航（全职开发机工作）。

8月中旬至9月中旬（第三阶段：新模块接入真管道与端到端验证）。核心任务：将模拟环境下验证通过的三个新模块接入真实事件流。张航将correlation.detect_correlations()、baseline.update_from_event()与detect_deviation()、process_tree.update_from_event()接入start.rs事件消费循环，并将它们的告警写入取证日志。ProcessTree关联类型（correlation.rs中ProcessTree分支）从返回None改为实现真正的父子进程行为组合检测。刘晨执行六攻击场景端到端验证：反弹Shell（bash -i + TCP 4444）、勒索软件（批量.encrypted写入+原文件删除）、提权攻击（chmod u+s + sudoers修改）、DNS隧道（高频UDP查询）、Rootkit（insmod + /proc异常）、正常基线（ls/cat/wget等日常操作），确认规则命中+关联告警+基线偏离+取证哈希链完整。王磊将watch子命令改为实时显示真实内核事件流。赵颖编写端到端验证报告。陈昊协调刘晨测试脚本与张航开发排期、确认验证场景覆盖评审关注的攻击类型。预期成果：六攻击场景端到端验证全部通过、关联引擎和基线检测在真实数据下工作、取证哈希链防篡改验证完成。负责人：张航（接入开发）、刘晨（验证执行）。

9月中旬至10月上旬（第四阶段：性能基准与内核阻断实现）。核心任务：量化系统性能并启用阻断机制。张航执行性能基准测试：无探针基线→有探针→高负载（每秒10万事件）→不同规则集组合，测量探针延迟、事件吞吐、CPU占用、内存占用。多内核兼容测试至少验证5.15和6.1两个版本。bpf_send_signal阻断机制启用：在验证器通过后将infer_event返回值2（需阻断）的探针改为调用bpf_send_signal(SIGKILL)终止恶意进程，并用模拟攻击脚本验证阻断效果。刘晨设计对照组和记录数据：三组对照（无探针/有探针/高负载）×两个内核版本，记录延迟、吞吐、CPU、内存的量化数据。王磊在status命令中加入性能指标实时显示。赵颖编写性能测试报告（包含对照数据和目标值对比）。陈昊确认性能数据格式满足评审可对比要求、组织答辩素材中的技术数据部分。预期成果：性能基准数据达到目标值（探针延迟小于1微秒、吞吐大于10万条每秒、CPU小于5%）、阻断机制在模拟攻击下验证有效、跨内核兼容确认。负责人：张航（性能测试和阻断开发）、刘晨（数据记录）。
